# PastePing 误报率基准

> 本文件记录由 `tools/fp_benchmark.py` / `tools/fp_lab.py` 实测得到的**真实数字**，
> 用于回答本产品最关键的「它会不会经常误报、把用户逼到关掉总开关？」。
> 本产品核心成功标准是「不误报」——因此本基准刻意偏向真实办公场景中**高频出现、
> 却不应被提醒**的文本（寒暄、免责声明、引用块、破折号、常规业务表达、
> 含 16+ 连续数字的业务 token）。

## 元信息

- 被测版本：PastePing v0.2（含 2026-10-06 降误报修订）
- 运行方式：`python tools/fp_benchmark.py`（纯标准库，无参数，可直接跑）
- 全组合扫描：`python tools/fp_lab.py`（枚举 2^6 = 64 种杠杆组合，不修改任何源码）
- 评测口径：正类 = `alert`（应当提醒）
- 样本规模：**52 条**（干净样本 36 条 / 应报正样本 16 条）
- 判定：`TP` 应报且报 / `FP` 不应报却报 / `FN` 应报未报 / `TN` 不应报且静默

## 一、修订前 vs 修订后（同一个基准集）

| 指标 | 修订前 | **修订后（当前上线档位）** |
| --- | ---: | ---: |
| TP / FP / FN / TN | 16 / 21 / 0 / 15 | **16 / 3 / 0 / 33** |
| **总误报率 FPR** | 58.3%（21/36） | **8.3%（3/36）** |
| **总漏报率 FNR** | 0.0% | **0.0%** |
| 精确率 Precision | 43.2% | **84.2%** |
| 召回率 Recall | 100.0% | **100.0%** |
| F1 | 0.604 | **0.914** |

**一句话结论：误报率从「每 5 条干净办公文本约 3 条被误报」降到「每 12 条约 1 条」，
且召回率仍是 100%（16 条应报样本全部命中，零漏报）。**

## 二、降误报的做法：语义词共现门槛

原始 6 条建议中，**真正有效的是「语义词共现门槛」，而不是「位置收紧」**。
`tools/fp_lab.py` 的单杠杆实测（相对「全关」基线 58.3%）：

| 杠杆 | 说明 | 单独 FPR | Δ 误报数 | 召回代价 |
| --- | --- | ---: | ---: | ---: |
| `ai_boundary` | AI 特征贴身首尾（窗口 200 字 → 8 字） | 55.6% | **−1** | 0%（但实质削弱规格） |
| `disclaimer` | 「仅供…参考」需批注语义词 | 52.8% | −2 | 0% |
| `structure` | 行首 `>` / `——` 需批注语义词 | 47.2% | −4 | 0% |
| `bracket` | `【…】` 需内文含批注语义词 | 52.8% | −2 | 0% |
| `bankcard` | 16–19 位数字需 Luhn 或邻近上下文词 | 44.4% | −5 | 0% |
| `low_signal_keywords` | `注：`/`备注：`/`请确认`/`请审阅` 需强语义词 | 44.4% | −5 | 0% |

> ⚠️ **`ai_boundary` 是唯一「性价比不成立」的杠杆**：它单独只减少 1 条误报，原因是
> 误报样本里的「没问题」「好的我」本来就位于文本第 0 字，位置再收紧也打不到；
> 而它的代价是把 AI 特征的有效识别窗口从产品规格写死的「首尾各 200 字」收窄到 8 字。
> 因此**刻意不启用**（`detector.TIGHTEN["ai_boundary"] is False`），
> 并有 `tests/test_detector_tighten.py::test_ai_boundary_off_keeps_200_char_window` 锁定。

### 达标组合的阶梯（全组合穷举，召回全程 100%）

| 组合 | 误报率 | 精确率 | 备注 |
| --- | ---: | ---: | --- |
| 全关（修订前） | 58.3% | 43.2% | 21 条误报 |
| `ai + disc + brkt`（最初设想的「稳健档」） | 52.8% | 45.7% | ❌ 远达不到目标 |
| `disc + struct + brkt` | 36.1% | 55.2% | |
| `disc + struct + brkt + bankcard` | 22.2% | 66.7% | |
| **`disc + struct + brkt + bankcard + kw`（当前档位）** | **8.3%** | **84.2%** | ✅ 残留误报全在寒暄 |
| 再加 `ai_boundary`（6 杠杆全开） | 5.6% | 88.9% | 代价：AI 窗口 200 → 8 字 |

> 说明：最初把「位置收紧」划为低成本档、把「结构模式语义词 / 银行卡校验」划为激进档，
> 是**基于建议清单里乐观的预期收益标注**，与实测不符。实测后按数据重排了优先级。

## 三、当前仍存在的 3 条误报（8.3%）

| 误报样本 | 触发规则 | 根因 |
| --- | --- | --- |
| 「没问题，我稍后处理这个工单。」 | `开头特征:没问题` | AI 残留词表中「没问题」区分度低 |
| 「好的我知道了，这就去办。」 | `开头特征:好的我` | 同上 |
| 「你想吃什么？需要我帮你带饭吗？」 | `结尾特征:需要我帮你` | 「需要我帮你」在人类对话中也常见 |

**根因是 AI 残留词表本身的低区分度，而非门槛问题**：前两条（「没问题」「好的我」）位于
文本第 0 字，位置再收紧也拦不住；第三条（「需要我帮你」）确实能被 `ai_boundary` 拦住
（这正是 6 杠杆档位比当前档位再少 1 条误报的来源），但代价是把 AI 窗口从 200 字收窄到
8 字，不值得。可能的下一步（**尚未实施，需先决策**）：

| # | 方案 | 预期收益 | 预估召回代价 |
| --- | --- | --- | --- |
| A | **词表收敛**：移除「没问题」「好的我」，只保留高区分度的「当然可以」「以下是」 | −2 条 | 会漏报「好的我马上帮你处理这个问题。」类真实 AI 残留，约 **−5%** |
| B | **交付语境门槛**：AI 开头特征需同句出现交付性动词（整理/总结/方案/帮你 …） | −2 条 | 无引导动词的 AI 输出会漏报，约 **−5% ~ −10%** |
| C | **同规则连续忽略自动静音**（体验优化，不改单次判定） | 0（但打扰感下降） | 无 |

## 四、复现方式

```bash
cd pasteping
python tools/fp_benchmark.py    # 当前档位的 FPR / 精确率 / 召回率
python tools/fp_lab.py          # 64 种杠杆组合的 Pareto 前沿与达标组合
python -m pytest -q             # 304 项测试（含 tests/test_detector_tighten.py 档位锁定）
```

`fp_benchmark.py` 末尾会打印：`[3] 按规则分组的误报统计`、`[4] 疑似误报样本清单`、
`[5] 漏报样本清单（当前为空）`。

## 五、已知局限

- 样本集为**人工构造**（52 条），非大规模真实语料抽样，误报率为**方向性参考**而非精确值。
- 样本偏重「容易误报」的办公口语/格式，刻意压力测试误报面，故 FPR 高于随机抽样文本。
- **语义词门槛的召回代价在本样本集上恰好为 0，但这不代表真实语料上也为 0**——
  例如「请确认」出现在**没有**内部语义词的真实内部批注里，修订后会被静默。
  扩样本时请重点补这一类「无强语义词的真内部批注」，这是当前最可能的漏报面。
- 未覆盖：真实剪贴板的格式（富文本/图片/文件）路径、非中文语境、超长文档的实际分布。
- 建议后续迭代把它扩成 200+ 条更全面的**合成**样本（语料全部人工构造，不涉及任何真实剪贴板数据）。
