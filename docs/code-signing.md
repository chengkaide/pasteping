## 一、为什么未签名会被拦

未签名的 exe 在**从网页下载**的机器上双击时，SmartScreen 会弹出：

```
Windows 已保护你的电脑
Microsoft Defender SmartScreen 阻止了无法识别的应用启动。
                                        [ 不运行 ]   ← 显眼
更多信息 →                                          ← 很小，很多人不会点
```

要点：

- 「不运行」按钮很显眼，「更多信息」是个不起眼的小链接 —— 有实测数据表明，
  **未签名分发的安装完成率大约只有六成**（约 62%），其余大多卡在这一屏。
- 想继续必须点 **更多信息 → 仍要运行**。
- 消除这一屏有**两条**路：① 用真实 CA 签发的证书；② 让文件**不带网络标记**（见下面一小节）。
  自签名证书对本机以外**完全无效**，不算一条路。

### 但有个关键前提常被忽略：这一屏是「网络标记」触发的

`Mark of the Web`（MotW）是 Windows 给**从网络下载来的文件**加的一个隐藏数据流
（`Zone.Identifier`）。SmartScreen 的"已保护你的电脑"那一屏，主要由它触发。

**推论**：如果一个 exe **没有 MotW**（例如它是同事用 U 盘拷给你的、由包管理器安装的、
或你手动解除了锁定），那么即使它未签名，双击时**也不会出现那一屏**。

> **本仓库已实测确认（2026-10-07，Windows 11 家庭版 build 26200）** —— 见第七节。
> 三个内容完全相同（SHA256 一致）的副本，只有网络标记一项不同：
> **无标记 → 正常启动；带标记 → 被拒绝执行并弹出「Windows 已保护你的电脑」；
> 带标记后解除锁定 → 恢复正常启动。** 网络标记是**唯一开关**。

**而且 PastePing 少了一层麻烦**：本仓库实测 `dist\PastePing.exe` 的清单是

```
requestedExecutionLevel level="asInvoker" uiAccess="false"
```

`asInvoker` 意味着**它不申请管理员权限**，所以**不会触发 UAC 提权弹窗**，
也就不会有那个常见的「未知发布者：是否允许此应用对你的设备进行更改？」。
换句话说，**PastePing 未签名时只有一个障碍，就是 MotW 触发的那一屏。**

## 四、拿到证书之后怎么做

**每次重新打包都必须重新签名。** PyInstaller 每次都会生成一个全新的文件，
签名不会自动跟着走 —— 把「打包 → 签名」当成一个不可拆分的动作写进发布流程。

### 1. 本仓库已经带了签名工具

```bash
python tools/sign_exe.py --hash                                   # 看大小、SHA256、签名状态
python tools/sign_exe.py --sign --pfx cert.pfx --password 口令      # 用 pfx 文件签
python tools/sign_exe.py --sign --thumbprint <证书指纹>             # 证书已装进系统时
python tools/sign_exe.py --sign --pfx cert.pfx --password 口令 --dry-run   # 只看命令不执行
```

脚本会在签名后自动用 `signtool verify /pa /v` 核验，并复述 SHA256。

> 用 **Certum SimplySign 云签名**时，证书会以"虚拟智能卡"的形式出现在系统里，
> 直接用 `--thumbprint` 那个用法即可，本机不落任何私钥文件。

### 2. 它背后跑的命令（等价于手写）

```cmd
signtool sign ^
  /fd SHA256 ^
  /td SHA256 ^
  /tr http://timestamp.digicert.com ^
  /f  cert.pfx /p 口令 ^
  dist\PastePing.exe

signtool verify /pa /v dist\PastePing.exe
```

- **`/fd SHA256` + `/td SHA256`**：文件摘要与时间戳摘要都用 SHA256（SHA1 已被淘汰）。
- **`/tr <时间戳服务器>` 极其重要**：带上时间戳，证书过期后已发布的签名**依然有效**；
  不带时间戳，证书一过期，用户那边签名立刻变成无效。
- `signtool.exe` 随 **Windows SDK** 提供（也可 `winget install Microsoft.WindowsSDK.10.0.22621`）。

### 3. 证书放哪

- **一律不要提交进仓库**（本仓库 `.gitignore` 已忽略 `*.pem`；pfx 也要一并忽略）。
- 口令同样不要写进脚本或提交记录。
- 用**云签名**（Certum SimplySign）时私钥存在 CA 的 HSM 里，本机不落盘，
  自然没有 pfx 泄露的问题 —— 这也是下面推荐 Certum 个人版的原因之一。

## 五、签名能解决什么、不能解决什么

**能**：

- 消除 SmartScreen 的首次拦截（OV 需要一点信誉累积时间）；
- 用户能在文件属性里看到**你的真实名字**，而不是「未知发布者」；
- 文件被篡改能被用户察觉（哈希与签名不符）。

**不能**：

- **不能保证零警告**：OV 签名的前若干次下载仍可能提示，信誉要累积；
- **不能消除杀软误报**（那属于启发式/云查杀，另说）；
- **不能防止别人解包**：Python 打包的 exe 用 PyInstaller 解包工具就能拆开，
  签名只证明「这是谁发的」，不证明「里面看不到」。

## 七、实测记录：MotW 与 SmartScreen 的真实关系（2026-10-07，已完成）

**结论先行：网络标记（MotW）就是唯一开关。**

### 实验设计（控制变量）

取同一个 `dist\PastePing.exe`，复制三份，**三份内容的 SHA256 完全一致**
（`a43ec2e6…8054d`），唯一差别是网络标记：

| 样本 | 网络标记 | 模拟的现实场景 |
| --- | --- | --- |
| **A** | **无** | U 盘拷贝 / 包管理器安装 / 手动解除锁定 |
| **B** | **有**（`ZoneId=3` + `HostUrl`） | 从网页下载 |
| **C** | 有，随后**删除** | 下载后右键「解除锁定」/ `Unblock-File` |

用 `os.startfile()` 启动 —— 与在资源管理器里双击走的是**同一条 `ShellExecute` 路径**。

### 结果

| 样本 | ShellExecute 返回 | 进程是否启动 | 是否弹窗 |
| --- | --- | --- | --- |
| **A**（无标记） | 正常 | ✅ **起来了** | 无 |
| **B**（有标记） | ❌ `WinError 1223 操作已被用户取消`（`ERROR_CANCELLED`） | ❌ **没起来** | ✅ **弹出「Windows 已保护你的电脑」** |
| **C**（标记已删） | 正常 | ✅ **起来了** | 无 |

B 弹出的就是这一屏（实机截图，非示意图）：

![Windows 已保护你的电脑](img/smartscreen-block.png)

### 由此确定的几件事

1. **没有 MotW 就一定不会被拦** —— 这是**确定**结论，不是推测：A 与 B 的唯一变量就是标记。
2. **「解除锁定」确实有效**（C 已验证），可以放心写进下载页。
3. **从网页下载一定带标记**，所以「直接给 exe 下载链接」这条路**必然遇到这一屏**，
   除非用户自己解除锁定，或者你做了签名。
4. **`ERROR_CANCELLED`（1223）才是这件事的机器层面真相**：不是"弹窗挡了一下"，
   而是 Shell **拒绝创建进程**。没有父窗口的自动化调用下，它甚至会**静默拒绝、连弹窗都不给**
   —— 也就是说在某些脚本/自动化场景里，用户连"仍要运行"的机会都没有。
5. **`asInvoker` 清单确实管用**：全程没有出现 UAC「未知发布者」提权框，
   唯一的障碍就是上面这一屏。

### 附：两个技术细节（以后写自动化测试有用）

- **Windows 11 的 SmartScreen 窗口不是 `#32770` 对话框**：它窗口类名是 `Static`、
  标题是 `Window Dialog`，内容由内部承载。按 `#32770` 去找**找不到**它。
- ShellExecute 在等用户对弹窗做选择时**会阻塞**；若发起进程先退出，
  弹窗随之消失（等于用户没做选择，程序不会启动）。

### 仍未实测的一项（诚实标注）

**包管理器（winget / scoop / choco）下载后的文件到底带不带 MotW** —— 本次因网络受限
（`curl` 走代理返回 502、`Invoke-WebRequest` 连不上）**未能验证**。它取决于各包管理器
内部的下载器（有的走 BITS、有的走自己的 HTTP 栈），**不能靠推理下结论**。
所以下载页应当只承诺**已经实测有效的「解除锁定」**。
